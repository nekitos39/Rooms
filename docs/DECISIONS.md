\# DECISIONS — Выбор стека и обоснование решений

\## Обоснование решений



\### 1. Vite вместо Webpack



Vite даёт быстрый dev-сервер (ES-модули вместо бандла), быстрый HMR и простую прод-сборку. Требует Node 20.19+ / 22.12+.



\### 2. React + TypeScript



\- Компонентный подход, хуки.

\- TS ловит ошибки на этапе разработки.

\- Большая экосистема библиотек (MUI, MSW, axios).



\### 3. MUI вместо собственного UI-кита



\- Готовые компоненты (Table, Chip, Button, TextField, Tabs).

\- Консистентный вид из коробки.

\- Экономит время на верстку.



\### 4. MSW вместо реального backend



\*\*Причина:\*\* ТЗ лабы №1 требует «приложение работает без сервера: все данные — локальные».



\*\*Как работает:\*\* MSW перехватывает HTTP-запросы на уровне Service Worker и возвращает мок-ответы. Компоненты не знают, что работают с моком.



\*\*Плюсы:\*\*

\- Не нужен backend для демо.

\- Работает оффлайн.

\- Легко переключиться на реальный API — просто убрать `worker.start()`.



\### 5. In-memory + MSW вместо IndexedDB



\*\*ТЗ рекомендует IndexedDB\*\*, но допускает localStorage для малых объёмов.



\*\*Решение:\*\* данные хранятся в \*\*in-memory\*\* внутри MSW-моков. Экспорт/импорт — через JSON-файл, что покрывает требование переноса данных.



\*\*Почему не IndexedDB:\*\*

\- Больше кода (асинхронные транзакции, курсоры).

\- Для учебного проекта избыточно.

\- Перенос данных реализован через JSON — это требование ТЗ.



\*\*Что улучшить в будущем:\*\*

\- Перейти на IndexedDB с библиотекой `idb` или `dexie`.

\- Добавить версионирование схемы.



\### 6. Хранение времени в UTC



\*\*Проблема:\*\* в разных локалях `new Date().toString()` даёт разные результаты.



\*\*Решение:\*\*

\- В хранилище — всегда `toISOString()` (UTC, RFC 3339).

\- В UI — `toLocaleString('ru-RU')` (локальная таймзона).

\- При вводе `datetime-local` — `new Date(localInput).toISOString()`.



\### 7. CSS-модули + MUI sx



\- \*\*Глобальные стили\*\* — CSS-модули в `Components/\*/\*.module.css`.

\- \*\*Локальные\*\* — через `sx` prop MUI.



\### 8. Docker (опционально)



Docker Compose в репо для:

\- Воспроизводимого запуска на Windows/Linux.

\- Возможности развернуть полный стек (frontend + backend + Postgres + NGINX).

\- Для лабы №1 \*\*не требуется\*\*.
